# 匍匐专用动作

> 适用问题：玩家在 `Pose.SWIMMING` 爬行/匍匐时执行打药、换弹、手雷蓄力、投掷与近战挥砍。
> 不包含游泳、滑铲、睡觉、骑乘与死亡；这些状态由各自频道负责。

## 目标与边界

- 站姿动画的手臂/头部目标不能直接叠到爬姿上，否则头朝地、手插地。
- 动作期间平滑进入侧躺，结束后回到当前爬行姿势；站起时快速回正。
- 动作识别必须来自真实玩家/模组状态，不能只凭“手里拿着什么”让状态永久成立。
- 自制动画由 `analysis/prone/*.json` 生成，内置模型中的动画 JSON 不是第一作者源。
- 不改变服务端换弹、弹药、投掷物生成或任何其他玩法事实。

## 频道与状态所有权

`PlayerControllerCollection` 中 `player.prone` 位于 `use`、`fire`、`swing`、`hold` 之后，因此可以覆盖它们写入的骨骼。频道过渡长度为 0；平滑由 `kinetic.prone_roll` 统一提供，不能再叠一份控制器淡入。

`ProneAction` 为每个玩家保存：

- `roll`：0..1 的侧滚进度。趴下起手 0.15s、动作结束回位 0.24s；站起用 0.08s 收尾。
- `kind`：`NONE / MEDICAL / RELOAD / GRENADE / SWING / THROW / OTHER`。动作信号消失后仍保留到 roll 归零，回位继续使用同一段动画。
- 挥砍段数：两段交替；只有上一段进度达到 70% 才推进，窗口外的连点重放当前段。
- 投掷蓄力快照：只用于识别脱手消耗，不驱动物品状态。

趴姿判定排除真正游泳、滑铲、骑乘、死亡、睡觉与旁观。动作在站立途中开始时，状态保留 `armedCatchUp`，随后趴下会直接接回该动作的侧躺姿态。

## 动作识别

### 打药、手雷蓄力与吃喝

优先读 `player.isUsingItem()` 和 `getUseItem()`：

- 医疗分类或注册名医疗关键词 → `MEDICAL`；
- 可投掷物且不是 `EAT/DRINK` → `GRENADE`，同时记录蓄力物品快照；
- 吃喝 → `OTHER`，只接管躯干与头腿。

频道动画名只作兼容回退。**单纯持有手雷不再产生 `GRENADE`**，否则 roll 永远不会退出。副手使用也不能冒充主手动作。

### 换弹

TaCZ 客户端接受换弹输入时先发出 `GunReloadEvent(CLIENT)`，服务端 `ReloadState` 随后同步。为覆盖这段真实空窗：

1. `TacEvent` 记录短暂、纯表现层的换弹提示，并绑定事件的 `gunId`；切枪、空手、到期都会失效。
2. `TacCompatInner.isReloading` 合并本地提示与服务端同步状态，供 Fire 动画选择和匍匐检测共用。
3. `GunFirePredicate` 只对换弹绕过普通挥动/使用互斥门；开火与近战仍遵守原门。
4. 本地提示到期但同步尚未到达时，正在播放的 `tac:reload:*` 继续接力，不中断已有的一次性动画。

提示不修改 `IGunOperator`、弹药、玩家使用状态或任何服务端数据。Superb Warfare 仍走它自己的同步状态。

### 投掷

投掷分为三个不同阶段，不能合并为一个“手里拿着雷”的状态：

- **蓄力**：真实使用状态产生 `GRENADE`；
- **脱手**：主手 `swinging`，或蓄力结束后物品确实被消耗/主手变空，产生一次 `THROW`；
- **随挥**：当前 `PLAY_ONCE` 仍在播放就维持 `THROW`，播完后才进入 detach 与 roll 回位。

`swing` 频道已经播放 `prone:throw` 时，匍匐频道只提供 roll，不叠第二套动画。若 swing 没有接手，匍匐频道自己播放 `prone:throw`。同名一次性动画完成后，只有新的真实 `THROW` 输入沿才允许 `indicateReload()`；回位阶段绝不重播。

没有 use、swing、消耗变化或模组事件的第三方投掷，通用层无法可靠推断脱手；应增加对应适配器，而不是用关键词伪造动作。

## 侧滚与落地

所有使用类动作通道采用：

```text
kinetic.bone_rot('<bone>').<axis> * (1-kinetic.prone_roll)
    + <target> * kinetic.prone_roll
```

因此 roll=0 时逐位等于底层动画。`MAllBody` 承载侧滚与高度补偿；`AllBody`/`AllHead` 归零，避免其他模组的身体补偿把侧躺再拧一次。头部单独用较快的混合系数，避免身体已躺下而头仍扎地。

- 通用、换弹、持雷、投掷、挥砍：70°；打药：50°。
- 右臂与头不参与落地补偿，否则主动作会把身体高度拖着走。
- 左臂仅在它确实是支撑臂时参与补偿。换弹与拔销时左手要离开地面操作物品，姿态源用 `left_support=false` 改为由躯干/腿确定接触高度。
- 需要微调的接缝可以显式设置 `comp`；持雷与投掷共用同一补偿，保证蓄力末帧到投掷首帧连续。
- 挥砍、持雷与投掷不写腿部通道，主频道的爬行循环继续驱动下肢。

目标角度写入前由 `prone_author.py` 选择最短分支并保证逐帧连续。多关键帧通道使用 Catmull-Rom；离线审查工具必须采用同一插值，不能用线性采样冒充运行期结果。

### 挥刀力量感与接地

挥砍不是匀速绕肩：中段由伸直的持刀手臂完成前向水平横扫，手腕明显前伸并从右向左扫过；命中段之后以平滑曲线减速收回。0.75s 时长参照站立持刀水平挥砍段，而非空手挥动。第二段从同一预备位反向挥出，连招窗口避免从半空硬切到另一段起手。

`prone:hold:sword` 是挥砍首末帧的同一组局部手臂角度。该角度同时检查未侧滚的爬行状态与完全侧躺状态，刀身沿前臂延长线、刀尖位于身体前方；不再从垂刀插地的姿势起收。

姿态更换仍使用按归一化进度接力：趴下↔站立时，`playAnimationSeeked` 只在动画名变化时 seek，新动画从相同比例的位置继续。`AnimationPlayer` 的 pending seek 在真正加载下一段时生效。

## 生成与审查

```bash
python3 analysis/prone_build.py --dry-run
python3 analysis/prone_build.py
python3 analysis/prone_check.py swing
python3 analysis/prone_review.py swing --frames 9 --views side,q --sword --out renders/swing.png
```

- `prone_build.py` 从姿态源重新生成 Alex/Steve 两套资源，并自动同步反手段。
- `prone_check.py` 检查固定补偿下的接地、真实手持挂点的刀尖、头部侧倾与手部/头部包围盒风险。
- `prone_review.py` 按 Catmull-Rom 采样输出逐帧、多视角条带；`--sword` 会把测试长刀并入同一深度排序。
- 主观视觉审查与数值检查都需要做；单项通过不能替代另一项。实际物品模型的 display 变换仍以游戏内渲染为准。

当前离线结果：挥砍与反手段的刀尖全程在地面以上；持剑预备位在未侧滚/完全侧滚两种状态下均不穿地；持雷末帧与投掷首帧的骨骼矩阵仅存在浮点误差。测试覆盖动画存在、分支与肘部限制、动作映射、换弹门控/枪身份、投掷回退/重放沿以及跨姿态接力。

实机组合与联机高延迟仍按[动画已知问题](../../status/known-issues/animation.md)验收，离线通过不等于实机验收完成。

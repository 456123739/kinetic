# 匍匐（趴下）专用动作：侧躺过渡、匍匐挥刀、开火时腿部继续爬行

> **适用问题**：玩家处于 `Pose.SWIMMING`（趴/爬行，且不在游泳、不在滑铲）时，
> 打药 / 换弹 / 手雷蓄力为什么会变成"头朝下、手插进地里"，趴下挥刀为什么往地面砍，
> 以及趴下开火时腿部爬行动作为什么会停。
> **不包含**滑铲（见 `slide-lock.md`）、游泳、攀爬。

## 现象与根因（实测数值）

离线复现工具 `analysis/prone_pose.py`（按运行期语义叠加频道，见下）在
`climbing` 之上叠加各动作动画后测得：

| 场景 | 头前向量（-Z 为前） | 头前倾角 | 最低点 | 穿地骨骼 |
| --- | --- | --- | --- | --- |
| 打药 `use_mainhand:medical` | (0.35, -0.89, 0.30) | 62° | -4.86 | 手/前臂/头 |
| 换弹 `tac:reload:rifle` | (-0.26, -0.95, 0.16) | 72° | -9.68 | 左手/前臂/头 |
| 手雷蓄力 `tac:mainhand:grenade` | (0.04, -1.00, 0.05) | 86° | -6.00 | 左手/前臂 |
| 匍匐持枪 `tac:climbing:rifle` | (0.02, -0.05, -1.00) | 3° | -1.28 | 前臂/袖子 |

根因有三层，全部来自"动画是站姿写的，身体是躺着的"：

1. **头**：`climbing` 的 `Head` 是 `[-90, kinetic.head_yaw, 0]`——那 -90 正好抵消 `Root`
   的躺姿旋转，让脸朝前。任何站姿动画写 `Head`（+12、-5、+6…）都会把这 -90 顶掉，
   头于是顺着躺姿往下扎。前倾角 62°~86° 就是这么来的。
2. **手**：手臂的局部旋转相对胸腔，而胸腔法线在趴下时朝地面（`(0.24, -0.96, 0.10)`）。
   "双手在胸前"于是等于"双手往地里伸"，前臂/手成为全模型最低点。
3. **腿**：`tac:climbing:*` 与 `tac:climbing:fire:*` 自带 `Root` / `AllBody` / `DownBody` /
   双腿 / 双脚轨道。运行期每个频道是**绝对值覆盖**（`AnimationProcessor.visitBoneQueue`），
   于是主频道 `climb` 的爬行循环被这些静态轨道顶掉——爬行时腿部看起来"停住"。

## 目标

- 趴下做打药 / 换弹 / 手雷蓄力 / 投掷时：先**平滑转侧躺**（70°），动作在侧躺姿态里完成，
  结束后**平滑转回**匍匐；终态最低点 ~-0.3（压在体面上，不悬空、不穿地）。
- 侧躺时头朝前、微微朝手，不再低头扎地。
- 趴下挥刀：独立的**前向横砍**弧线，不再朝地面砍；不破坏站姿挥砍。
- 趴下移动 + 开火：腿部爬行循环**不中断**（下肢只由主频道负责）。
- 不修改任何站姿动画的行为。

## 机制

### 1. 状态机 `ProneAction`

`client/animation/ProneAction.java`，形状与 `SlideLock` 一致（每玩家一份状态、渲染线程、
`player.isRemoved()` 时清理）：

- `float roll(Player)`：0↔1 的平滑值。进入 0.30s、退出 0.34s，缓入缓出（smoothstep），
  行内按"上一次观测的渲染时间"推进，与动画时间同源，掉帧也不会跳变。
- `Kind kind(Player)`：`NONE / MEDICAL / RELOAD / GRENADE`。**不看游戏内部状态**，
  而是读其他频道**本帧已经选中的动画名**（`player.use` / `player.fire` / `player.hold_mainhand`），
  因此对 TaCZ、卓越前线、以及将来任何往这些频道塞动画的联动都自动成立。
  蓄力/使用结束、动作动画停播后仍**锁住 kind** 直到 roll 退回 0，保证回滚用的是同一段动画。
- 进入条件：趴（`pose == SWIMMING && !isSwimming() && !sliding && onGround`）+ kind ≠ NONE。
  滑铲、游泳、骑乘、死亡、睡觉一律不进。

### 2. molang 变量 `kinetic.prone_roll`

`KineticBinding` 增加 `var("prone_roll", ctx -> ProneAction.roll(ctx.entity()))`。
它是全部侧躺姿态的唯一驱动量：动画里所有被改写的通道都写成

```
kinetic.bone_rot('<骨骼>').<轴> * (1 - kinetic.prone_roll) + <目标角度> * kinetic.prone_roll
```

这样 roll=0 时**逐位等于**底层动画写下的值（不是"接近"），侧躺进出在任意底层姿势下都连续，
不会因为底层正处在爬行循环的某个相位而跳变。

> 函数必须挂在 `kinetic` 根下：引擎只把 `query/math/v/c` 提升到顶层，裸写 `bone_rot(...)`
> 会被当成变量查找并解析失败（`PronePoseDataTest` 用运行期同一个绑定集钉住了这一点）。

计时用 `renderTicks`（tick，每秒 20 个）：单帧推进夹在 2 tick 以内，掉帧不会跳过整段动画。
曲线是 smoothstep，两端一阶导为 0，所以起手与收尾都不会有"起步一顶"。
动作种类在动作动画停播后仍保留到 roll 归零，回滚用的因此一定是同一段动画（否则回滚会换姿势）。

### 2.1 侧滚写在哪根骨骼上

`MAllBody`。理由：它是 `Root` 之下所有可见骨骼的唯一汇聚点（`AllBody`/`UpBody`/手臂/腿都在它
下面），而**没有任何会在趴下时播放的动画写它**——`swim`/`elytra_fly`/`riptide`/`gui` 与
`parcool` 的水下动作用到它，但那些状态全被进入条件排除。

这一点决定了整个方案的"零回归"性质：`MAllBody` 只写
`rotation = [0, -68°*roll, 0]`、`position = [0, 0, comp*roll]`（局部 z 对应世界 +Y），
roll=0 时它就是恒等变换，与改动前逐位一致；不需要去改 `Root`，也就不会和
`climbing` / `climb` / TaCZ 的 `Root` 轨道打架。

侧滚轴正好是世界的 +Z（身体长轴），所以头部只要在 `Head` 的 **Y** 通道上加
`head_roll * roll` 就能抵消侧滚（已由 FK 验证：`Head` 局部 Y 轴 = 世界 Z 轴）。

**不要用 `Head` 的 Y 通道去"把头摆正"**：侧躺时 Y 是绕身体长轴转，会把头**转到肩膀上**——
实测右臂∩头的穿透从 1.7（爬行基线）涨到 4.4，看起来就是"胳膊埋在脑袋里"。

人侧躺想看前方，是绕**世界竖直轴**回头，落到骨骼上是 `Head` 的 X/Z 组合。现在的做法是给每个
`prone:*` 一个**显式头部目标** `"head": [x, y, z]`，由 `analysis/prone_head.py` 反解：
给定想看的俯仰角，在一组解里取"肩部穿模最小"的那一个。

| 动作 | Head 目标 | 视线 | 肩部穿模 |
| --- | --- | --- | --- |
| 通用侧躺 | [-90, 20, 5] | 平视 0.2° | 1.78（基线 1.71） |
| 打药 / 换弹 | [-85, 20, 20] | 下俯 14.3°（看手） | 2.05 |
| 手雷蓄力 | [-90, 10, 10] | 下俯 5.1°（看前方） | 1.74 |
| 投掷 | [-90, 20, 5] | 平视 0.2° | 2.4 |

这几个值允许每个 `prone:*` 单独覆盖；`head_roll`/`head_pitch` 只作为旧路径的回退。

落地补偿 `comp` 由"侧滚后身体（不含手臂）最低点停在 **0.60**"反解得到，按 roll 线性上升。

这个值一度取到 2.05（为了让手臂不穿地），结果实测 `UpBody` 最低点在 2.05、全身最低点却是左袖 0.74——
**躯干悬空 2 单位、只有手臂贴地、双脚吊在半空**，观感就是"悬浮"。用户明确要求"躺在上面"、
并且允许下侧腿略微穿地。现在压回 0.60，并把左腿从 `LeftLeg X=-8` 改成 **-20**（腿顺着地面伸出去，
脚落到地面）；代价是终态最低点略低于 0（-0.26 ~ -0.35，即 0.02 格），属于"压在地面上"。

### 2.2 为什么不是 90°，以及下压那只手必须收进来

按 90° 侧躺是一个**刚体绕身体长轴旋转**，接地那一侧的手会连同肩一起被转到地面以下：
肩关节在躺姿下本来就贴着地面，任何"挂在肩上"的手臂立方体都会沉下去 1.5~2 单位。
实测 68° 时最低点 -5.83，90° 时 -2.4~-6.5，都不合格。

所以最终取 **35°**（用户口中的"有一定倾斜角度的侧躺"），并且把**下压那一侧（左）手臂收进胸前**：
`LeftArm ≈ [-296,-21,-141]`、`LeftForeArm ≈ -164`（前臂几乎折满，手落在身体中线上）。
手臂贴着躯干走，滚动时几乎不改变高度；另一侧（右手，拿物品的那只）随身体一起转上去，天然离地。

实测（打药 / 换弹 / 手雷蓄力，各自的多个动画时刻）：

| 角度 | 打药 | 换弹 | 手雷蓄力 |
| --- | --- | --- | --- |
| 68° + 不收手 | -5.83 | -6.76 | -5.83 |
| 35° + 收手（最终） | **-0.17** | **+0.46** | **+0.40** |

### 3. 频道 `player.prone`

`PlayerControllerCollection` 在 `use` 之后注册（保证覆盖 use/fire/swing/hold 的写入），
谓词按 `kind` 选动画：

| kind | 本模型自带的动画 | 回退 |
| --- | --- | --- |
| MEDICAL / RELOAD / GRENADE / OTHER | `prone:action:idle` | — |
| 模型自带同名专用动画时 | `prone:action:<kind>` | `prone:action:idle` |

**内置模型只用一段通用姿态**：它写 `MAllBody`（侧滚 + 落地补偿）、`Head / AllHead / AllBody`
（头摆正、侧滚补偿、把站姿的 `head_yaw` 补偿压平）、`UpBody / UpperBody / 双腿 / 双脚`（侧躺的身体与腿）。
**它不写手臂**——手臂继续由 use/fire/hold 频道的原动画驱动，于是注射、拔弹匣、抬雷这些原有动作细节
全部保留，而且手臂跟着身体刚性侧滚，不存在"角度插值走长弧把手甩进地面"的路径问题。

专用动画的入口留着：模型若提供 `prone:action:medical` 等，谓词会优先用它；没有就回退到通用姿态。
`PronePredicateMappingTest` 钉住了这条回退。

写 `Root` / `DownBody` / 手骨是不允许的：前者属于主频道，后者由原动作动画负责，避免互相顶掉。

`AllBody` 必须一起压平：TaCZ 的站姿动画在上面写了
`(kinetic.head_yaw<0)?(-kinetic.head_yaw):(0)`（站着时让肩膀跟着头转）。趴下时 `AllBody`
的局部 Y 轴正好是世界侧滚轴，玩家往左看就会把侧躺的身体再拧最多 75°。

### 3.1 角度分支：为什么要"归一"

混合是逐分量角度插值（引擎本身就这么插），因此目标的**写法**会影响**路径**：目标写 `+101°`
而底层是 `-180°` 时，插值会走 281° 的长弧，手臂中途扫进地面。写入时对每个分量在
`目标 ± 360k` 中挑一个到"站姿动画姿态"与"爬行姿态"距离之和最小的写法——姿态完全相同，
只是插值走短弧。这一步由 `analysis/prone_author.py` 的 `resolved_targets()` 自动完成，
姿势文件里写错分支也不会出问题。

`AllBody` 压平与分支归一这两条都是"照抄数值会踩"的坑，`PronePoseDataTest` 与
`sweep` 各自钉住一半。

### 4. 匍匐挥刀与投掷

`SwingPredicate` 现在**每帧**按趴姿选一遍：站姿解析出的名字含 `throwable_potion` 就走
`prone:throw`，其余走 `prone:swing`；模型没有对应动画则保持原行为。站起来的那一帧立刻回到
站姿弧线，不会再继续演匍匐动作。

两者都是**侧躺**动画（`MAllBody` 承载 70° 侧滚），由 `player.prone` 的 `ProneAction.Kind.THROW`
驱动 roll；都不写腿部通道——腿跟着 `MAllBody` 一起侧转，同时继续播主频道的爬行循环。

- `prone:swing`：**侧躺平挥**。手在**同一水平面**上从右后方 (8.5,11.2,3.0) 扫到身前
  (3.1,11.2,-10.5) 再到左前 (-1.9,10.9,-9.7)，然后沿同一条前方走廊收回；手部高度全程
  8.3~13.2（前期有约 5 单位的自然起伏，不是举过头顶再劈下）。
  早期版本是"过头斜劈"（手抬到 y=17.4），观感太高、不像趴着挥刀，已改掉。
- `prone:throw`：手从体侧 (7.0,12.2,2.5) 抬到头顶上方 (4.9,17.5,-6.1)，向前下方甩出
  (4.4,10.3,-10.6)，再回到体侧。

> 为什么不能沿用站姿弧线：趴平时肩膀只有 4 单位高、头与躯干就在旁边，手臂只能贴着身体小幅摆动
> （视觉上"拘谨、不舒展"）；站姿投掷更是把手甩到身体前下方，等于往地里扔，并且整段穿过躯干
> （实测右臂∩头 5.1）。侧躺 70° 后手臂能在头顶那块空域活动，两个动作的最差穿透都回到
> 2.1 / 2.7（爬行基线 1.71）。

**关键帧连续性**：姿势文件里每个分量都按 `±360k` 吸附到"离上一帧最近"的等价角度
（`enforce_continuity`）。只对齐首帧是不够的——后续关键帧落到差 300° 的分支上时，逐分量插值会走长弧，
中间几帧手臂会甩到诡异的方位（实测投掷的随挥段因此穿头 6.2）。

### 5. 下肢单一来源

`tac:climbing:*`、`tac:climb:*`、`tac:climbing:fire:*`（共 18 段，两个模型各一份）删掉了
`Root / AllBody / DownBody / 双腿 / 双脚` 共 162 个通道，下肢从此只可能来自主频道的
`climb` / `climbing`。

这些轨道原本是 `climbing` / `climb` 的**拷贝**，所以静止持枪时的姿势与原来逐值相同；
不同的是 `Root` 位置（`(0,2,19)` vs `climbing` 的 `(0,5,19)`）与 `AllBody` 抬升，等于把整个
身体压低约 1 单位——这也是匍匐持枪时前臂插进地面 1.28 单位的来源。删掉之后：

| 动画 | 改前最低点 | 改后最低点 |
| --- | --- | --- |
| `tac:climbing:rifle` | -1.28 | -0.28 |
| `tac:climbing:fire:rifle` | -1.28 | -0.28 |
| `tac:climb:rifle`（移动） | 腿被冻住 | -0.84（腿恢复爬行循环） |
| `tac:climbing:rpg` | — | -1.15 |

移动时的爬行循环由 `climb` 继续驱动：实测在 `tac:climbing:fire:rifle` 同时播放的情况下，
一个循环内左脚位移 2.4 单位、膝盖位移 1.3 单位——腿在动，不再冻住。

## 5.5 场景与判定（"途中改姿势"也要无缝）

用户报的第二类问题是"动作已经开始、播放途中才趴下"。状态机把三件事分开看：
**动作是否还在进行**（`active`，由 use/fire/hold 频道的当前动画推断）、**此刻是否趴着**（`prone`）、
以及**这一轮是什么动作**（`kind`，只在趴着时锁存）。四种组合的去向因此是确定的：

| 情形 | 侧躺 | 说明 |
| --- | --- | --- |
| 站着做动作 | 不侧躺（roll 恒为 0） | 站着不该有侧躺状态，`kind` 也不锁存 |
| 站着做动作 → 途中趴下 | **直接落到 70% 侧躺**，再 0.07s 收尾；动作继续 | 底层动画没换，`bone_rot` 混合的起点就是当时那副站姿，因此不跳变；同一 `kind` 让侧躺用同一段动画 |
| 趴着做动作 → 动作结束（仍趴着） | 0.34s 慢慢回位到匍匐 | 回位走 `bone_rot`，回到的是"当时正在爬的那一帧" |
| 趴着做动作 → 途中站起来 | 0.12s **快速**收掉 | 底层已经是站姿/死亡动画，慢退会留下 0.3s"站着举着侧躺的胳膊" |
| 趴下投掷（`prone:throw`） | 侧躺（`Kind.THROW`） | 动画由 swing 频道播、本频道只推 roll；站起来即回站姿弧线 |
| 滑铲中做动作 | 不侧躺 | 滑铲被 `SlideLock` 排除；滑铲结束后如果还在 `Pose.SWIMMING` 且动作没结束，立刻接上侧滚 |
| 动作信号丢 1~2 帧 | 保持不动 | 0.12s 的 detach 容忍，换弹的一次性动画播完不会让身体滚回去再滚出来 |
| 回位途中又接上一个动作 | 从当前值继续升 | `progress` 不复位，不会"先归零再重来" |

"动作早就开始、玩家途中才趴下"这一条有个额外处理：那一刻本身就是离散的姿态切换（站 → 趴），
所以直接把 `progress` 落到 0.7，而不是从 0 慢慢滚——否则会有 0.2 秒"站姿手臂压在躺姿身体上、
整个人陷进地里"的过渡帧。头再用 **1.8 倍速**的混合系数（`math.min(1, kinetic.prone_roll*1.8)`），
约 0.13s 就摆正：实测 catch-up 起始帧头前倾 5.1°（原本要 34°）。

挥砍（`prone:swing`）是同一类问题的另一面：它由 `SwingPredicate` 在**挥砍起始帧**
（`swingTime == 0`）决定用站姿还是趴姿的弧线，并且如果频道已经在播 `prone:swing` 就继续播完——
挥到一半趴下/站起来都不会换动画重播（那会看起来"抽一下"）。

## 验收

每个阶段都要过两道关：

1. **数值**：`analysis/prone_author.py info` 断言终态（roll=1）的头前倾角、最低点、双手位置；
   `sweep`（roll 0→1 采样 11 帧）断言**过渡不比两端更差**。

   > 注意验收线的定义：roll=0 那一端正是"站姿动画叠在躺姿上"的坏姿势（打药 -4.86、换弹 -9.68、
   > 手雷 -6.00），拿它当绝对阈值不可能通过。`sweep` 因此打印
   > `起点 X → 终点 Y，过程最小 Z，验收线 W`，要求 `Z ≥ W`（两端最差值再放宽 0.8 单位）。
2. **渲染**：`analysis/prone_qa.py` 把"侧滚 6 档 × 2 视角"或"挥砍 6 帧 × 2 视角"拼成一张图，
   逐帧人工检查（不只看关键帧）。

外加数据断言测试 `PronePoseDataTest`：每个 `prone:action:*` 动画必须
（a）所有被写的通道都含 `kinetic.prone_roll`，（b）写 `AllBody` 并压平，（c）不得写
`Root/DownBody/手`，（d）`bone_rot` 指向的骨骼必须存在；`prone:swing` 不得写腿；
`tac:climb*` 不得写下肢与根。`ProneWiringTest` 再用常量池与源码顺序确认频道注册、
注册顺序（必须在 `use`/`swing` 之后）、以及 molang 变量确实暴露。

### 美术侧工具链（都在 `analysis/`）

| 脚本 | 用途 |
| --- | --- |
| `prone_pose.py` | 多频道姿态叠加 + 固定机位渲染（地面参与深度排序，能看出插地） |
| `prone_author.py` | 候选姿势的 `info`/`render`/`sweep`/`wrap`；`wrap` 生成带 roll 混合的动画片段 |
| `prone_solve.py` | 两骨手臂反解：给定手腕世界坐标，搜出上臂/前臂角度 |
| `prone_qa.py` | 侧滚或时间轴的逐帧验收图 |
| `prone_build.py` | 一次性重生成四段动画并合并进两个内置模型 |

姿势源头只有 `analysis/prone/<动作>.json` 一个文件；`wrap` 输出的片段由脚本统一生成，
因此四段动画用的是同一套混合表达式、同一个侧滚角度与落地补偿。

## 不变量

- roll=0 时，任何主频道的动画输出逐位不变。
- 滑铲锁定、游泳、骑乘、死亡、睡觉不进入本状态。
- 站姿的 `use_mainhand:medical` / `tac:reload:*` / `tac:mainhand:grenade` / `swing:sword` 数据不动。

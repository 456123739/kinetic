# TaCZ 静态网格补丁：实机验证清单

开关：`config/kinetic-client.toml` → `tacz.StaticGunMesh = true`（默认 `false`）。
对应提交：`673d467`（注入）、`32ca9c3`（分帧烘焙）、`5d8117f`（子树校验）。

## 它做什么

每把枪第一次出现时，分帧（每帧一块，11~16 帧）把 TaCZ 骨骼树烘成模型空间顶点并上传一份 VBO；
之后每帧不再发射任何顶点，只提交 11~16 次绘制。

实测（真实自带枪包模型，CPU 侧）：
- 即时模式：AK74M 243 µs、MK18 195 µs、db_long 35 µs；
- 烘焙后只算矩阵：6.4 / 2.4 / 2.4 µs；
- 块数：14 / 16 / 11。

## 必须确认的四件事

1. **拉栓 / 换弹 / 瞄具切换**：这些动作会改动骨骼，`movedSinceBake()` 必须让它整把回退到原路径。
   观察点：开镜时准星是否与不开补丁时一致；换弹动画是否完整。
2. **光照变化**：从室外走进室内、火把旁。当前实现是整段重传，理论上不闪；若闪，说明光照值没有生效。
3. **接缝**：块与块之间是否出现缝隙或重叠（说明块矩阵与原路径的父链不一致）。
4. **首次持枪**：背包里第一次拿出某把枪的 11~16 帧内是否有掉帧或"枪只出现一半"。

## 出问题时怎么回退

- 关掉 `tacz.StaticGunMesh` 即可，不需要重装；
- 运行期任何异常、任何骨骼变动、任何上传失败都会**自动**落到 TaCZ 原路径，只影响那一帧；
- 日志关键字：`[TaCZ] static gun mesh disabled`（永久回退）、`fell back for a frame`（单帧回退）。

## 已知未验证项

- 真实 GPU 上每块绘制是否落在 1~2 µs（软件渲染测不出，只能用 F3 帧时间对比）；
- 光影（Oculus/Iris）下复用 TaCZ 的 `RenderType` 是否会与阴影 pass 冲突；
- 多把枪同屏时 10 MB 预算的淘汰策略是否造成反复重烘（观察是否出现周期性卡顿）。

## 与布娃娃无关

这个开关只影响 TaCZ 枪械渲染，不触碰 KINETIC 自己的模型、动画与布娃娃路径。
